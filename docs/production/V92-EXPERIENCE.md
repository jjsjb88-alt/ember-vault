# V9.2 — 관찰과 선택, 중단 후 이어하기

기록일: **2026-11-06, Asia/Seoul**.

V9.2는 V9.1의 18단계 학습 동선과 개인 결산을 유지하면서, 지도를 읽는 시간·현재 상태에 맞는 표식·유인 전 판단·연습 이어하기를 개선한다. 본게임의 20개 방과 기존 저장·최고 기록은 유지한다.

[본게임](https://jjsjb88-alt.github.io/ember-vault/dist/?v=20261106c) · [첫 금고 털이](https://jjsjb88-alt.github.io/ember-vault/dist/?v=20261106c&tutorial=1)

실행 결과와 검수 수치는 [V9.2 검증 기록](V92-VERIFICATION.md)에 둔다. 이 문서는 구현된 흐름과 한계를 설명하며, 이전 버전의 검수 수치를 새 결과로 재사용하지 않는다.

## 지도를 열어도 관찰 단계는 끝나지 않는다

소리를 처음 살펴보는 `sound` 단계와 귀환 전 숨결을 확인하는 `forecast` 단계에는 별도의 관찰 상태가 있다. 지도를 열거나 닫는 것만으로 다음 단계로 넘어가지 않는다. 플레이어가 **「지도 확인 · 계속」**을 눌러야 그 단계가 끝난다. 버튼에는 현재 관찰 단계의 식별자가 연결되어 다른 단계의 확인으로 건너뛰지 않는다.

지도 관찰 중에는 이동이나 전투를 진행하지 않는다. 조작을 시도하면 먼저 지도를 확인하라는 안내를 받으며 자원·적·턴은 변하지 않는다. 전투 표시줄과 하단 행동판, 원래 코치와 주변을 어둡게 만드는 강조막을 숨긴다. 대신 지도와 소리·적·숨결 보고서, 확인 버튼을 함께 배치한다. 가로 화면에서는 보고서를 지도 옆에, 세로 화면에서는 아래에 둔다. 내용이 많으면 보고서 안에서 스크롤한다.

관찰 중 새로고침해도 저장된 단계와 지도 열림 상태를 함께 복원한다. 확인하지 않은 지도를 읽었다고 처리하거나 같은 엔진 행동을 다시 실행하지 않는다. 별도의 일반 지도 사용과 달리 이 두 단계는 읽기와 확인을 위한 단계다.

관련 구현: [tutorial.js](../../dist/tutorial.js)의 `observe`, `tutorialAdvance`, `tutorialMapLesson`; [app.js](../../dist/app.js)의 지도 확인 처리; [v9.css](../../dist/v9.css)의 지도 관찰 배치.

## 방 표식은 현재 상태를 설명한다

방의 원래 종류가 아니라 지금 살아 있는 적과 사용 여부를 먼저 확인한다.

| 실제 상태 | 표식 |
| --- | --- |
| 현재 살아 있는 적이 있음 | 전투 |
| 적이 떠났거나 쓰러진 적 전용 방 | 빈 방 |
| 상자를 이미 사용함 | 회수 완료 |
| 유물을 이미 회수함 | 유물 회수 완료 |
| 쉼터·상인·제단을 사용함 | 휴식 완료 / 물약 품절 / 정화 완료 |
| 윈치를 사용함 | 지름길 개방됨 |
| 개방된 9↔17 승강 연결로 이동 | 승강 통로 |

적이 있는 상자나 유물 방은 우선 전투로 표시한다. 적이 사라지면 남은 상호작용을 표시하고, 이미 사용했다면 완료 상태를 표시한다. 글자가 「회수 완료」라고 해서 이동 소음까지 없어지는 것은 아니다. 바닥과 소음 표시는 별도로 유지한다.

관련 구현: [strategy.js](../../dist/strategy.js)의 `routeAdvice`.

## 돌을 던지기 전에 다음 반응을 본다

유인 모드에서 방을 고르면 바로 기술을 쓰지 않고 예고 창을 연다. 목표 방, 기술 1·소리 5, 관측한 적의 다음 반응을 보여 준다. **「이 방으로 유인 · 기술 1」**을 눌렀을 때 실제 유인이 실행된다. **「다른 방 선택」**으로 취소하면 기술·경계·메아리·적 위치·추출 순서는 바뀌지 않는다.

예고는 현재 상태를 복제해 유인과 적의 다음 턴 반응을 계산한다. 원본 상태를 실행용으로 바꾸지 않는다. 이동하는 적은 출발 방과 다음 방을, 자리를 지키거나 아직 듣기만 하는 적은 그 반응을 구분해 보여 준다. 플레이어가 있는 방으로 들어오는 적은 별도로 경고한다. 이미 같은 방에 있는 적의 반격도 이동과 구분한다.

예고의 전제는 **“유인 후 추가 행동 없이 지금 위치에서 턴을 마칠 때”**다. 돌을 던진 뒤 이동·추가 소음·공격으로 상황을 바꾸면 적의 추적도 달라질 수 있다. 현재 관측한 방에 있는 적만 이름과 반응을 표시하며, 보지 못한 목적지는 「어둠 속」으로 표시한다. 예고에 적이 없다고 미탐색 구역 전체가 비었다는 뜻은 아니다. 전에 들은 소리를 따라 이동하는 적과 이번 유인 소리를 들은 적도 구분한다.

이 예고는 적의 다음 반응을 판단하기 위한 정보다. 이후 턴의 전체 피해·숨결·추출 결과나 안전한 귀환을 보장하지 않는다. 비용을 낼 수 없거나 유인이 허용되지 않는 상태에서는 예고 대신 해당 이유를 알린다.

관련 구현: [strategy.js](../../dist/strategy.js)의 순수 계산 `lureForecast`; [app.js](../../dist/app.js)의 예고·취소·확정 처리.

## 연습 저장은 행동이 끝난 시점부터

연습을 시작하거나 성공한 엔진 행동이 적용되면, 다음 안내 단계와 행동 기록을 계산해 **연출 완료 전에** 저장한다. 구매·공격·보상·유물 회수가 이미 규칙에 반영됐다면 애니메이션 중 새로고침해도 그 행동을 재실행하지 않는다. 저장 단위는 마지막으로 반영된 게임 상태이며 애니메이션의 재생 위치는 저장하지 않는다.

| 다시 여는 상황 | 이어지는 동작 |
| --- | --- |
| 진행 중 새로고침 | 현재 단계·방을 보여 주고 「이어서 플레이」「처음부터 다시」「기존 탐험 계속」 중 선택 |
| 지도 관찰 중 | 같은 관찰 단계와 지도 열림 상태 복원 |
| 전투 보상 선택 전 | 적을 다시 처치하지 않고 저장된 보상 선택 창 복원 |
| 실패 상태 | 저장된 실패 상황에서 선택 전 체크포인트로 재도전 가능 |
| 연습에서 명시적으로 나감 | 일시 중단 상태로 보관하고 본게임 복귀. 다음 접속에서 연습을 강제로 열지 않으며 메뉴에서 이어하기 |
| 처음부터 다시 | 연습 진행만 초기화하고 새로운 연습 시작 |
| 탈출 뒤 결산 확인 전 | 완료 상태를 이어서 열어 결산 확인 가능 |
| 결산으로 연습 종료 | 연습 진행 저장을 지우고 본게임 복귀 |

귀환 실패 후 재시도는 V9.1처럼 게임 상태·행동 기록·단계를 같은 체크포인트로 되돌린다. 버린 시도의 피해나 보상을 성공한 시도에 합치지 않고, 재시도 횟수는 유지한다. 이번에는 그 기록과 체크포인트도 별도 연습 저장에 포함되므로 새로고침 후에도 같은 기준으로 재도전할 수 있다.

본게임의 진행을 연습 데이터에 복사해 영구 보관하지 않는다. 이어할 때 브라우저에서 읽은 현재 본게임을 잠시 보관하고, 연습을 나가면 그 탐험으로 돌아간다. 연습 중 본게임 저장과 최고 점수는 갱신하지 않는다.

## 손상된 기록과 저장이 막힌 경우

연습은 브라우저의 별도 `localStorage` 키 `ember-vault-tutorial-progress-v1`을 사용한다. 저장 내용은 연습 상태, 진행 단계, 행동 기록, 재시도 체크포인트, 최근 안내, 지도 열림 여부, 일시 중단 여부다. 본게임 `ember-vault-save-v2`와 최고 점수 `ember-vault-best-v1`을 연습 진행 키로 재사용하지 않는다.

불러올 때 저장 버전·시나리오·단계 목록의 식별자, 게임 상태 형식과 자원 범위, 방·유물·적 정보, 현재 단계와 보상 대기 상태, 행동 기록·체크포인트의 일관성을 검사한다. 호환되지 않거나 손상된 기록은 연습용 키에서만 제거를 시도하고 사용하지 않는다. 화면에는 **“이전 연습 기록을 읽지 못했습니다. 본게임 저장은 유지되며 연습을 새로 시작할 수 있어요.”**라고 알린다. 손상된 데이터로 본게임을 덮어쓰거나 검증을 우회해 진행하지 않는다.

저장 접근 차단이나 용량 부족은 별도 실패 상태로 처리한다. 페이지를 닫거나 새로고침하면 최근 진행을 잃을 수 있다는 안내를 시작·진행·이어하기 화면에 표시한다. 현재 페이지의 메모리로 계속할 수 있는 것과 브라우저에 저장된 것은 구분한다. 이 기능은 같은 브라우저의 저장 공간에 의존하며 기기 간 동기화 기능이 아니다. 실제 휴대폰의 운영체제 강제 종료나 백그라운드 복원까지 확인했다고 주장하지 않는다.

관련 구현: [tutorial-storage.js](../../dist/tutorial-storage.js)의 저장·불러오기·검증·삭제 API, [app.js](../../dist/app.js)의 연출 전 저장과 재개 흐름. V9.1 문서의 「메모리 전용 행동 기록」은 당시 구현의 기록이며 V9.2에서는 별도 연습 진행에 함께 저장한다. 본게임 저장 형식은 그대로다.

## 검증과 배포 확인을 구분한다

로컬 Chromium의 실제 조작·새로고침·모바일 화면 및 터치 에뮬레이션 결과는 [V92-VERIFICATION.md](V92-VERIFICATION.md)에 기록한다. 자동 검사 수나 브라우저 통과 수는 이 문서에 중복 고정하지 않는다.

이번 작업 환경에서 공개 `github.io` 주소 직접 접속은 프록시 403으로 제한됐다. 따라서 로컬에서 게임이 열리고 연습을 마친 사실을 공개 주소를 직접 열어 확인한 것으로 쓰지 않는다. GitHub Actions의 배포 작업 결과 확인도 공개 주소의 직접 플레이 검수와 다른 증거이며, 확인한 실행과 범위는 검수·배포 기록에 따로 남긴다. 프록시의 거절만으로 공개 사이트 자체의 장애 여부를 판정하지 않는다.
