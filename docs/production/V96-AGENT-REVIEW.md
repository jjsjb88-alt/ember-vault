# V9.6 · 에이전트 리뷰를 반영한 첫 탐험

2026-11-07 Asia/Seoul. 기준 커밋 `eefb22e`(V9.5). 사용자 요청에 따라 네 역할의 에이전트가 기존 튜토리얼을 검토하고, 발견한 문제를 수정한 통합본을 다시 플레이했다. 요청과 무관한 원화 교체나 던전 확장은 이번 범위에 포함하지 않았다.

## 역할과 반영 결과

| 역할 | 기존판에서 관찰한 문제 | V9.6에 반영한 변화 |
|---|---|---|
| 초심자 관점 | 안내 전 행동이 활성화된 것처럼 보임. 자동으로 닫힌 지도를 또 닫으라는 지시. 결산 직후 B5·윈치·56점 안내가 몰림 | 아직 사용할 수 없는 조작을 비활성 표시. 중복 지시 삭제. 결산 위에 단일 목표와 첫 실전 준비 버튼 배치 |
| 전략 응용 | 자유 귀환에서 다시 쓰려던 합법적인 유인이 튜토리얼 허용 목록에 없어 거절됨. 선택 상자의 대가가 흐림 | 귀환에서도 유인 허용. 예고·비용·적 이동은 기존 엔진으로 처리. 선택 상자의 금화 5~7과 현재 소음 비용을 사전 표시 |
| 모바일 | 교역 첫 화면에서 카드의 이름·효과·가격이 아래로 밀림. 보상 효과가 약 8px | 녹스의 컷신과 얼굴을 유지하면서 작업대 배치를 압축. 세로 보상을 한 열로 바꾸고 효과 13px 확보 |
| 진행·저장 | 다음 경로 강조에 의존한 귀환과, 도움 여부를 구분하지 않는 완료 회고 | 귀환 기본값은 목표만 제시. 44px 도움 버튼으로 길 안내를 선택. 도움 사용 여부를 보존하며 기존 저장도 이어짐 |

귀환은 별도의 퀴즈나 새 필수 단계를 추가하지 않았다. 기존 18단계의 마지막 구간에서 배운 행동을 스스로 조합하도록 안내를 줄였다. 이동·지도·숨죽이기·유인·턴 넘기기·전투·후퇴·허용된 상자와 탈출을 실제 규칙으로 처리한다. 도움을 켜거나 꺼도 자원·위치·턴·RNG는 변하지 않는다.

첫 실전은 **유물 하나를 얻어 입구에서 탈출**하는 목표로 연결한다. 직업 선택의 시작 버튼을 누를 때만 새로운 20개 방 탐험을 만든다. 준비·직업 선택·취소 단계에서는 원래 탐험과 최고점 저장을 바꾸지 않는다. 취소하면 결산의 준비 버튼으로 돌아간다. 실제 시작 뒤에는 HUD의 목표도 유물 회수 전·귀환 중·입구 도착 상태에 맞춰 바뀌고 새로고침 후 유지된다.

## 통합 플레이에서 추가로 잡은 문제

- 행동 비활성화를 넣은 직후 다음 단계의 이동 버튼이 이전 단계의 상태를 유지했다. 단계 변경 때 전체 조작을 다시 그리도록 고쳤다.
- 새 도움 버튼이 낮은 가로 화면의 출구와 상자를 가렸다. 가로 귀환 코치를 280×53px로 줄이고, 강조할 경로와 별개로 모든 출구·상호작용·지도 버튼을 피하도록 배치했다. 관찰한 귀환 33개 상태, 버튼 중심 111회 검사에서 가림 0이었다.
- 도움 버튼을 다시 그리면서 키보드 포커스가 사라지면 다음 Space가 턴 종료로 전달될 수 있었다. 새 버튼에 포커스를 돌려주고 연속 Space 입력 뒤 상태 불변을 확인했다.
- 첫 실전 준비를 취소하면 준비 버튼으로 돌아갈 수 없었다. 취소 버튼과 Escape 모두 결산으로 복귀하며, 원래 탐험의 미선택 전투 보상도 정상 복원하도록 고쳤다.
- 도움을 다시 끈 실행을 독립 귀환으로 기록하지 않도록 사용 이력을 별도로 남겼다. 오래된 안내 포함 귀환·완료 저장도 안내를 받은 실행으로 유지한다.

## 검증과 증거

- 런타임 24모듈 문법 검사, **테스트 101개 통과**. 실제 엔진으로 독립 귀환의 두 번째 유인·변위·빈방 통과, 소음 수정치, 저장 왕복, 기존 기록, 첫 실전 목표를 검사한다.
- 모바일 세 화면에서 실제 터치로 교역·전투·보상·유물·귀환·결산까지 완주. 첫 교역의 이름·효과·가격과 보상 세 개의 효과가 최초 화면에 보인다. [모바일 리뷰](V96-MOBILE-REVIEW.md), [원시 결과](V96-MOBILE-RESULTS.json).
- 390×844 추가 실행에서 공격 연출 중 새로고침, 보상·지도 복원, 키보드 도움 전환을 확인했다. 자연스럽게 도달한 귀환 저장에서 새 메타데이터 두 필드만 제거한 명시적 호환 fixture로, 이전 귀환과 완료 기록의 해석도 검사했다.
- 360×640 별도 전체 실행에서 튜토리얼 완료 → 첫 실전 준비 → 기사 선택 → 취소 → 다시 준비 → 명시적 시작 → 새로고침을 검수했다. 시작 전 원래 탐험·최고점 문자열 동일, 시작 후 20개 방·기사·첫 목표 유지. 본게임의 첫 승리까지 검수한 것은 아니다.
- 전략 담당은 도움 없이 서고11로 다시 유인해 파수병을 6→7로 옮기고 6→2→1→0을 통과했다. **T4·HP18·금화16·86점·귀환13턴 남음**으로 탈출했다. 예고와 실제 이동이 같았고 기술은 한 번만 소비했다. 사후 추가한 네 번째 회고는 실제 두 번째 유인→변위→빈방 통과가 연결될 때만 나온다. 이 회고 추가분은 엔진 테스트로 검증했으며 기존 브라우저 캡처에는 추가 전 문구가 남아 있다.
- 명시적인 별도 복구 fixture에서 기존 탐험에 미선택 보상이 있는 상태와 옛 완료 연습을 결합해 준비 취소·원래 보상 모달 복귀·저장 불변을 검사했다. 이를 정상 플레이 결과와 구분했다.

## 저장 호환과 한계

본게임 저장 키와 최고점 키, 연습 저장 버전1·시나리오 `first-ember-2`·18개 단계 키와 순서는 유지한다. 새 도움 필드는 선택적 boolean이며, 예전 기록에서 필드가 없었다는 사실도 저장 왕복에서 유지한다. 예전 귀환/완료 저장은 안내를 사용한 것으로 재개한다. 유인 회고에 새 저널 필드나 버전은 추가하지 않았다. 첫 실전 목표는 명시적으로 시작한 새 탐험의 표시용 필드로 제한된다.

에이전트 리뷰와 로컬 Chromium 터치/화면 검증이다. 처음 하는 사람의 학습 성공 평가나 실제 휴대폰/Safari 검수가 아니다. 공개 Pages 주소의 직접 브라우저 접속은 환경 프록시403으로 제한되므로 로컬 실행과 GitHub Actions 배포 성공을 구분한다. 이번 개선은 관찰된 완료 방해와 전달 문제를 해결한 것이며, 사람 초심자가 규칙을 이해하는지는 후속 플레이테스트로 확인해야 한다.
