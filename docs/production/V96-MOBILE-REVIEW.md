# V9.6 · 모바일 에이전트 리뷰와 통합 검수

2026-11-07 Asia/Seoul. V9.5를 실제 조작하며 발견한 문제를 수정한 뒤, V9.6의 실제 index 페이지와 CSS로 다시 확인했다. [전체 결과 JSON](V96-MOBILE-RESULTS.json), [대표 화면](../visual/implemented/v96-mobile/).

## 리뷰에서 확인한 문제와 개선

1. **작은 교역 화면에서 상품의 선택 근거가 숨음.** V9.5의 360×640 첫 상품은 y533~781에 놓여 그림만 보였고, 이름·효과·가격은 아래였다. 740×320에서도 첫 상품이 y240~398에 놓여 비용이 숨었다. 기존 자동 클릭은 버튼을 스크롤해 이 문제를 지나갔다. 튜토리얼 작업대에서 인물 얼굴을 보존하며 원화 영역을 압축했고, 최초 화면의 상품 이름·효과·가격을 별도로 측정했다.
2. **보상 선택 근거가 원화보다 지나치게 작음.** V9.5의 360px 3열은 100px 원화와 약8px 효과 텍스트를 함께 넣었다. 세로에서 68px 원화·15px 이름·13px 효과의 1열 선택행으로, 낮은 가로에서 64px 원화·13px 효과의 3열 카드로 바꿨다. 실제 세 선택지의 효과가 모두 최초 화면 안에 있는지 확인했다.
3. **새 독립 귀환 코치가 가로 화면의 출구·상자를 가림.** V9.6 통합 검수 중 740px에서 이끼 서고 출구를 대화 버튼이 덮었고, 첫 수정 뒤에는 서고의 상자 중심을 종료 버튼이 덮었다. 가로 코치를280×53px로 압축하고, 본문10.5px/15px·최대3줄·내부 스크롤과44px 도움 버튼을 유지했다. 루트는 경로 강조 여부와 분리한 회피 영역과 버튼 중심 가림의 큰 페널티를 추가했다. 이후 세 화면에서 모든 허용 출구·현재 방 상호작용·지도 버튼의 실제 중심 hit를 검사했다.

일반 그림·효과·비용·목표 본문을 삭제하거나 JavaScript 강제 클릭/자동 스크롤로 가림을 통과시키지 않았다. 새 가로 코치에서는 장식적인 단계 제목·피드백·대화 재생 버튼을 감추고 목표와 도움·닫기를 남긴다. 긴 목표 본문은 내부에서 스크롤한다.

## 최종 통합 결과

| 실제 브라우저 화면 | 첫 spark 이름 하단 | 효과 하단 | 가격 하단 | 보상 원화/효과 | 완주 |
|---|---:|---:|---:|---|---|
| 360×640 터치 | 479.6px | 505.4px | 570.4px | 68px / 13px | PASS |
| 390×844 터치 | 479.6px | 505.4px | 570.4px | 68px / 13px | PASS |
| 740×320 터치 | 189.7px | 214.5px | 280.4px | 64px / 13px | PASS |

세 화면 모두 대화 완료 직후의 첫 작업대이며 스크롤 위치0을 확인했다. 이름·효과·가격이 실제 모달/화면 안에 들어오는지 확인했다. 보상은 세 선택지 각각의 이름과 효과 위치·13px 글자 크기를 확인했다. 예고·지도 확인·전투·보상·유물·귀환·결산까지 실제 버튼으로 진행했고 JavaScript/HTTP 오류가 없었다.

귀환의 기본값은 도움 꺼짐이며, 다음 경로를 가리키는 coach-target이 없음을 확인했다. 도움은44px 이상으로 화면 안에 있다. 360px과740px에서는 도움 켜기 → 실제 새로고침과 이어하기 → 도움 끄기를 수행했다. 남은 자원·위치·RNG 등 게임 상태는 같고 도움 사용 기록은 남았다. 결산에서도 해당 실행은 도움을 사용한 귀환으로 표시된다. 390px 실행에서는 도움을 쓰지 않은 귀환 표시를 확인했다.

귀환 중 행동 뒤의33개 화면 상태에서 버튼 중심을 총111회 `document.elementFromPoint`로 확인했다. 도움 켜짐·꺼짐·재개 상태를 포함하며, 대상은 매번 보이는 허용 출구·상자/탈출 등 방 상호작용·지도다. 최종 검사에서는 모두 실제 대상이나 그 자식이 최상위 hit였으며, 같은 경로의 실제 터치 완주도 통과했다. 이는 경로상 관찰한 상태의 검증이며 모든 가능한 자유 경로의 기하를 증명하지 않는다.

최종 문구 정리에서 도움 버튼을 「도움 보기 / 도움 접기」로 줄였다. 이 변경 뒤 740×320 전체 완주·도움 재개·모든 관찰 조작 중심 검사를 다시 통과했으며 53px 코치와44px 버튼 크기는 같다.

검수 도구: [verify-v96-mobile.py](tools/verify-v96-mobile.py).

```bash
python3 -m http.server 8015 --bind 127.0.0.1 --directory .
# 별도 터미널. Python Playwright와 /usr/bin/chromium 필요
python3 docs/production/tools/verify-v96-mobile.py compact-map
python3 docs/production/tools/verify-v96-mobile.py portrait-touch

```

최종 통합 실행은 실제 index가 연결한 CSS를 사용했으며 스타일이나 게임 상태를 주입하지 않았다. 개선 전후 CSS만 확인한 중간 단계에서는 별도 V9.5 스냅샷과 CSS 주입을 사용했고 그 결과를 최종 통합 결과와 섞지 않았다. 실제 장치/Safari 인증이 아닌 Chromium의 화면·터치 에뮬레이션이다. 경로를 아는 에이전트의 정해진 조작 검사이며, 처음 하는 사람이 스스로 이해했는지 측정한 인간 학습 평가가 아니다.
