# 잿불 금고 · 규칙-서사 연결표

> B안 확정 · 문구 교체 설계안. **이 문서는 구현이 아니다.** `dist/` 미수정. 게임 수치·RNG·`ember-vault-save-v2` 불변.

## 적용 원칙

- 기존 텍스트만 교체한다. 버튼은 8자, 안내 문장과 제목은 40자 이하를 목표로 한다. `740×320`, `932×430`, `390×844` 실측 검수 전에는 반영하지 않는다.
- 공격력·이동력·기술·방어·소음·경계의 수치 표현을 지우지 않는다. `추출 → 행동 → 실제 소음 → 적 반응 → 용의 경계` 순서를 바꾸지 않는다.
- **추출된 소음은 즉시 발생하지 않는다.** `다음 개인 행동`의 첫 소음에 더해질 뿐이다. 돌멩이 유인에는 개인 행동 보정이 적용되지 않는다. 텍스트가 메커니즘을 거꾸로 설명해서는 안 된다.
- `잊힌 제단`과 `고요의 성소`는 같은 `shrine` 규칙으로 능력 하나를 풀에서 제거한다. `금지된 서고`는 능력 이름이지 독립된 방이 아니다. `파수병의 방`은 튜토리얼 전용으로 생성되는 이름이다.
- **교역 메뉴는 위치와 무관하게 열리며 기술로 능력을 구매한다.** 떠돌이의 쉼터는 **금화 5로 체력 8 회복**을 파는 별도 상호작용이다. 상인의 '남긴 목록'이라는 해석으로 현재 규칙과 맞춘다.
- 새 flavor 문장은 문서에서만 정의한다. 현재 740×320 화면에 빈 설명 슬롯이 검증되지 않았으므로 24종 flavor를 추가 표시하지 않는다. 승인 이후에도 능력 이름과 `CARDS[*].text`의 효과 문구는 수정 금지.

## 3. 적 5종: 현재 이름 유지

| 적 | 기존 출현 방식 | 짧은 서사 설명 | 구현 전제 |
|---|---|---|---|
| 금고의 파수병 | 튜토리얼의 적 이름 | 첫 발소리를 기억하는 수문장. | 튜토리얼 전용 이름, 일반 방 생성 목록 아님 |
| 묘지의 척후병 | 일반 적 후보 | 묘실의 울림을 좇는 오래된 병사. | `skeleton` 유형, 청취·조사·추적 |
| 방황하는 해골 | 일반 적 후보 | 돌아갈 길을 잊고 소리를 따른다. | `skeleton` 유형, 청취·조사·추적 |
| 유물 수호자 | 달의 봉인실·왕의 무덤 | 기억이 담긴 문턱을 지킨다. | 유물방 고정, 소리를 들어도 자리 고수 |

**구분:** 적 `잿불의 파수꾼`은 처치 가능한 방의 적이고, 경계 8 이상에서 턴 끝에 공격하는 **전역 용의 숨결**은 별도 시스템이다. 두 존재를 같은 개체라고 안내하지 않는다.

## 6. 구현 게이트 (승인 후에만)

1. 파일 교체 대상은 표의 **문구 리터럴**만. `dist/engine.js`도 `finish`, `interact`의 반환/사유 문자열만 손대고, 수치·RNG·턴·저장 구조는 그대로 둔다.
2. 수치가 포함된 템플릿(`소리`, `경계`, `공격·방어·HP`, `14턴 귀환`, `기술·금화`, `다음 개인 행동`)은 동적 정보 유실 없이 유지한다.
3. `npm run check`, `npm test` 후 740×320 / 932×430 / 390×844에서 코치·추출·소음·교역·결과 화면의 가림, 줄바꿈, 버튼 터치 영역을 점검한다.
4. 승인된 동작·저장 `ember-vault-save-v2`를 유지한다. C에 제안된 메타 해금은 이번 교체에 포함하지 않는다.
